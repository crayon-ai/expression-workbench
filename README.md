# 表达训练工作台

「简单复述」的可用版本：选一篇短材料，讲给小黄鸭听，录音会在你的设备上真的转成逐字稿，反馈和复述报告由后端的模型给出。可以再讲一遍，把两遍放在一起对照。「复杂表达」在工作台上能看见，还不能进入。

## 后端

前端静态文件和 `/api/*` 接口由同一个 Cloudflare Worker（`suntao-expression-api`）提供，网址：

```
https://suntao-expression-api.suntao-preview.workers.dev/
```

不再用 GitHub Pages，前端请求走同源相对路径 `/api/*`，不需要另外配置后端地址。接口细节见 `worker/README.md`。本地开发想让前端指向本机 Worker，可用环境变量 `VITE_API_BASE` 覆盖（默认同源）：

```bash
VITE_API_BASE=http://127.0.0.1:8787 npm run dev
```

进入「简单复述」选材料页时需要输入访问口令，前端调 `POST /api/check` 校验，通过后只存在这个标签页的 sessionStorage（key：`expression-workbench.access-code`），不进代码、不进构建产物。口令错了会提示「口令不对」，可以重输；页面上有「换一个口令」的入口。

## 模型

- 语音转写：在用户浏览器里本地运行，不用任何付费服务。模型是 k2-fsa 的 Zipformer CTC 中文小模型 `sherpa-onnx-zipformer-ctc-small-zh-int8-2025-07-16`（int8，59.8 MiB，Apache-2.0），用 `onnxruntime-web` 1.31.1 的 WebAssembly（SIMD、单线程）在 Web Worker 里跑。特征提取（Kaldi fbank）、CTC 解码、字节级 BPE 还原都在 `src/asr/` 里。
- 第一次进入复述页时下载：运行时 wasm（14.2 MiB，jsDelivr，失败换 npmmirror）+ 模型（59.8 MiB，ModelScope，失败换 Hugging Face、hf-mirror），共约 74 MB，页面显示进度和总大小；下载后校验 sha256，存进浏览器的 Cache Storage（`expr-asr-v1`），之后打开直接读本机缓存。
- 录音按停顿（≥0.4 秒）切成小段逐段识别，停顿处补「，」（≥0.9 秒补「。」），只补标点不改字；单段最长 20 秒。
- 浏览器不支持（没有 WebAssembly SIMD / Web Worker）或模型下载失败时，讲完会改成手动输入，并写明原因。
- 反馈和复述报告：智谱 `glm-5.3`。
- 反馈和复述报告：智谱 `glm-5.3`。

## 隐私

录音不上传：录音和转文字都在用户自己的设备上完成。只有点「看看小黄鸭听到了什么」或「获取复述报告」时，逐字稿文字会经我们的 Worker 发给智谱，不保存。逐字稿只留在页面里（刷新就没有），后端不存逐字稿。没有麦克风或转写失败时，会改成手动输入逐字稿，页面会写明这一点。

## 怎么打开

```bash
npm install
npm run dev
```

开发服务在 <http://127.0.0.1:4731>。构建：

```bash
npm run build
```

构建结果在 `dist/`，静态托管即可（资源用相对路径，hash 路由，不需要服务端配合）。

## 建议点一遍

1. 工作台首页。进入「简单复述」，先输入访问口令。
2. 选一篇材料，读完点「开始复述」。
3. 试音（声波一动就说明收到了），点「开始讲」，讲完点「讲完了」。
4. 「小黄鸭正在回想你说的话…」是本机转写进行中，会显示「第 n / N 段」；第一次用时如果模型还没下载完，这里显示下载进度。
5. 逐字稿页显示真实识别的全文，按句子切开。点某一句可以改掉识别错误。录音可以播放。转写没成功时会改成手动输入。
6. 点「看看小黄鸭听到了什么」，等小黄鸭想完，看反馈：哪里听懂了、哪里没跟上（引用可以点，会滚到那一句），然后揭开前提清单。
7. 「再讲一遍」讲第二遍。两遍逐字稿并排（窄屏上下叠），对照页里小黄鸭说哪里跟上了、哪里还是没跟上。
8. 想看评分就从反馈/对照页点「获取复述报告」：材料匹配度、逻辑完整性、语言流畅度，第二遍会和第一遍对比。

## 状态说明

两遍的录音、逐字稿、反馈、报告都放在页面内存里，刷新就没有，这是有意的。反馈按（材料，第几遍，逐字稿全文）缓存在内存里，改过逐字稿后会给「让小黄鸭重新听」的按钮，不会自动重算。
